## 原因と再発防止

### 何が起きたか

1. 最初は `/v1/images`（ノードのレンダリング）で書き出していた。これは Figma の
   マスク・トリミングが焼き込まれた「見たまま」の画像になる。
2. ただし角丸マスクが掛かったノードを **jpg** で書き出すと透過が無いので、
   **四隅が黒くなる**。
3. その黒を消すために、過去セッションで `scripts/refetch-masked.mjs` を使って
   **imageRef のオリジナル（マスク前の元データ）**へ差し替えた。
4. オリジナルにはトリミング情報が無いので構図が変わり、枠より小さい素材は
   引き伸ばされてぼやけた。

### 次回からの手順

1. **書き出しは必ず `/v1/images`（ノードのレンダリング）を使う。**
   `/v1/files/:key/images` が返す imageRef の URL（＝アップロード元データ）で
   置き換えないこと。トリミングが消える。
2. **マスク・角丸が掛かったノードは jpg ではなく png で書き出す。**
   四隅が黒くならず透過で抜けるので、CSS の `border-radius` をそのまま当てられる。
   （黒隅を理由に元データへ戻す、が今回の事故の入口だった）
3. **書き出し直後に自動チェックを掛ける。** `scripts/img-frame-audit.cjs` と同じ判定:
   - 素材の縦横比 と カンプの枠の縦横比 の差が 3% 以上 → ノード指定が違う
   - 素材の幅 < 枠の幅 x 2 → 解像度不足（2x を満たしていない）
4. **同じ実寸が何枚も並んだら疑う。** 1024x683 や 700x467 が10枚以上出てきたら、
   ほぼ確実に「フィルの元データをそのまま取った」状態。

> 3 は `~/.claude/skills/_shared/image-rules.md` の完了チェックリストに足す価値がある（未反映）。
