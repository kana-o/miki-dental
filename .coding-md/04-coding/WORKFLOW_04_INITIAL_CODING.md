# 工程 4: コーディング

## 概要

Figma MCP 経由でデザインを取得し、**セクションごとに** HTML と SCSS を順番にコーディングします。各セクションで必要な部分だけを取得することで、コンテキストを適切なサイズに保ちます。

**工程 3（コンポーネント検出）を実施している場合**: `CLAUDE.md` の「既存共通コンポーネント」を参照し、**共通コンポーネントを活用してから、各ページを include で組み立てる**流れにします。全体を一度書いてから共通パーツを抜き出して置き換える手間を避けます。

## 前提条件

- Figma MCP が接続されていること
- Figma で対象のデザインが選択されていること
- 工程 3 を実施した場合は、案件 `CLAUDE.md` の「既存共通コンポーネント」表が更新されていること

## 重要

- **position:absolute; の使用は原則禁止**
- **要素の並び順や位置は、Figma のノード情報（get_design_context で取得される位置情報）ではなく、スクリーンショットの見た目を参照して組み立ててください**
- Flexbox や Grid などの通常のレイアウト手法を使用し、実際の表示結果を基準にコーディングしてください

## 手順

### 1. Figma からデザイン構造を確認

まず、全体の構造を把握するために、Figma からデザイン構造を取得します：

```bash
# MCPツールを使用（自動実行）
# get_design_context を使用して全体の構造を取得
```

**重要: 画像取得について**

- **画像取得の指示がない限り、画像は取得しない**
  - デフォルトでは、`get_design_context` を使用する際も **画像は取得しません**
  - get_design_context を呼び出す際は dirForAssetWrites を指定しない
  - コーディング指示時は、画像取得について明記しない限り、デザイン情報（フォント、カラー、レイアウト、テキスト内容など）のみを取得してください
  - 新しい画像が必要な場合のみ、明示的に「○○の画像を取得してください」と指示してください
  - 画像は工程 2 で既に取得済みです（再取得は不要）

**注意**: この時点では全体構造の把握のみを行い、各セクションの詳細は後で取得します。

#### 1-1. ページ情報の確認

コーディング前に `.page-info/README.md` を確認し、対象ページのFigma URL・テンプレート・SCSS・デザイン画像を把握します。

#### インスタンス（コンポーネント）から情報を取得する場合

Figma のコンポーネントインスタンス（例: `h2_02` などのセクションタイトルコンポーネント）から情報を取得する際は、以下の点に注意してください：

1. **`get_metadata` の制限**

   - `get_metadata` では、インスタンスの構造（位置、サイズ、ノード ID）のみ取得できます
   - **インスタンス内のテキスト内容は取得できません**

2. **`get_design_context` を使用**

   - インスタンス内のテキスト内容を取得するには、`get_design_context` を使用します
   - `get_design_context` を使用する際は、**`dirForAssetWrites` パラメータを必ず指定**してください（ワークスペースのルートパスを指定）
   - 例: `dirForAssetWrites: "C:\\Users\\ikana\\OneDrive\\...\\{プロジェクト名}\\src\\img"`（プロジェクトルートまたは画像保存先の絶対パス）

3. **取得手順**

   ```
   1. Figma で該当のインスタンスノードを選択
   2. ノードIDを確認（例: "2084:12631"）
   3. get_design_context を実行（dirForAssetWrites を指定）
   4. 返されたコードからテキスト内容を抽出
   ```

4. **注意点**
   - `get_design_context` は React + Tailwind のコードを返しますが、これは参考情報として使用
   - 実際のコーディングでは、取得したテキスト内容をプロジェクトの規約に従って実装
   - 画像アセットは工程 2 で既にダウンロード済みのため、`get_design_context` で取得した画像パスは使用しない

### 2. セクションごとにコーディング

各セクションを順番に、**HTML → SCSS の順**でコーディングします：

**注意**: セクション名はプロジェクトごとに異なります。Figma のデザイン構造に従って、必要なセクションをコーディングしてください。

一般的なセクションの種類（プロジェクトによって名称や構成が異なります）：

- ヘッダーセクション
- ファーストビュー（ヒーロー）セクション
- 検索・フィルターセクション
- ニュース・お知らせセクション
- ピックアップ・特集セクション
- マップ・位置情報セクション
- スライダー・カルーセルセクション
- ギャラリー・写真セクション
- 情報・お役立ちセクション
- フッターセクション

#### 各セクションのコーディング手順

**セクション 1: {セクション名}**

1. **Figma から該当セクションのデザインを取得**

   - Figma で該当セクションのノードを選択
   - `get_design_context` を使用して該当セクションのみを取得
   - **重要**: 各セクションのノードを個別に選択して、テキスト内容やレイアウトを正確に確認すること
   - **重要: 画像取得について**
     - **画像取得の指示がない限り、画像は取得しない**
     - `dirForAssetWrites` は指定しない（画像は工程 2 で既にダウンロード済み）
     - コーディング指示時は、画像取得について明記しない限り、デザイン情報（フォント、カラー、レイアウト、テキスト内容など）のみを取得してください
     - 新しい画像が必要な場合のみ、明示的に「○○の画像を取得してください」と指示してください
     - 工程 2 で既に取得済みの画像は再取得しない

2. **HTML の作成**

   - `{メインHTMLファイル}` に該当セクションの HTML を追加
   - HTML 規約を遵守（後述）

3. **SCSS の作成**

   - `{SCSSモジュールディレクトリ}` に該当セクションの SCSS ファイルを作成
   - SCSS 規約を遵守（後述）

4. **確認**
   - HTML の構造が正しいか確認
   - SCSS が正しくコンパイルされるか確認
   - ブラウザで表示を確認
   - **Playwright でスクリーンショットを取得して確認**（後述）

**セクション 2 以降も同様に繰り返す**

### 3. HTML 規約 / 4. SCSS 規約（正本はSkill側・ここには再掲しない）

- **HTML規約・alt生成ルールの正本**: `html-check` Skill と `~/.claude/skills/section-impl/references/html-rules.md`（判定例は `~/.claude/skills/html-check/references/examples.md`）
- **SCSS規約15項目の正本**: `~/.claude/skills/_shared/scss-rules.md`

二重管理による更新漏れ防止のため、規約本文はSkill側のみを正とする。特に以下は旧版のこのドキュメントと現行ルールで**判断が逆転している**ので注意:

- カラーは「変数を使用」ではなく **Figma値とSCSS変数が完全一致する場合のみ変数使用**（不一致は16進数直書き。scss-rules.md ルール11）
- alt は「空文字禁止」ではなく **装飾画像は `alt=""`（空）が正**。コンテンツ画像のみ30文字以内の具体的なalt（html-check Skill）

**注意**: プロジェクトによってメイン HTML ファイル名（`index.html` / `index.php` 等）・SCSSディレクトリ構造が異なる場合があります。

### 5. Playwright によるスクリーンショット確認

コーディング後、Playwright を使用してブラウザのスクリーンショットを取得し、Figma デザインと比較確認します。

#### スクリーンショットスクリプトの使用方法

```bash
# 基本的な使用方法（SPビューポートでフルページキャプチャ）
node .coding-md/screenshot.cjs

# 特定セクションのみキャプチャ（CSSセレクタを指定）
node .coding-md/screenshot.cjs --selector ".l-footer" --viewport sp
node .coding-md/screenshot.cjs --selector ".l-header" --viewport pc

# SP/PC両方をキャプチャ
node .coding-md/screenshot.cjs --selector ".l-footer" --viewport both

# 出力ファイル名を指定
node .coding-md/screenshot.cjs --selector ".l-footer" --name footer

# Figmaデザインと比較
node .coding-md/screenshot.cjs --selector ".l-footer" --compare .page-info/designs/front-page.png
```

#### オプション一覧

| オプション | 説明 | デフォルト値 |
|------------|------|-------------|
| `--url` | 対象URL | 自動検出 |
| `--selector` | キャプチャするCSSセレクタ | なし（全体） |
| `--viewport` | ビューポート（sp, pc, both） | sp |
| `--output` | 出力ディレクトリ | 自動設定 |
| `--name` | 出力ファイル名のプレフィックス | screenshot |
| `--compare` | 比較対象のFigmaデザイン画像パス | なし |

#### セレクタの指定

`--selector` オプションでCSSセレクタを直接指定できます：

```bash
# セレクタを直接指定
node .coding-md/screenshot.cjs --selector ".l-footer" --viewport sp
node .coding-md/screenshot.cjs --selector "#main-content" --viewport pc
```

**注意**: プロジェクトごとにセクションのクラス名は異なります。実際のHTML構造を確認して適切なセレクタを指定してください。

#### 確認フロー

1. **問題が報告された場合**: まずスクリーンショットを取得して現状を確認
2. **修正後**: 再度スクリーンショットを取得してビフォー/アフターで比較
3. **Figmaデザインとの比較**: `--compare` オプションで並べて確認

#### 自動検出機能

スクリプトは以下を自動検出します：

- **開発サーバーURL**: `package.json`、`vite.config.js` などからポートを推測し、起動中のサーバーを自動検出
- **出力ディレクトリ**: スクリプトの場所を基準に自動設定

#### 注意事項

- 開発サーバーが起動している必要があります
- サーバーが検出されない場合は `--url` オプションで直接指定してください

## Figma MCP 出力ファイルの読み取り（最重要）

`get_design_context` の返却データが大きい場合、レスポンスは **ファイルに書き出される**。
インラインのレスポンスには「IMPORTANT: After you call this tool...」等のメッセージしか表示されない。

**必ず以下の手順を踏むこと:**

1. ツール実行後、レスポンスに `Large output has been written to: /path/to/file.txt` が含まれていないか確認する
2. 含まれていたら、**そのファイルを Read ツールで読む**（Grep で必要なテキストを検索してもよい）
3. インラインのメッセージだけを見て「テキストが取れなかった」と判断してはいけない
4. スクリーンショットの画像説明からテキストを推測して入稿してはいけない — 必ず `get_design_context` の出力ファイルから正確なテキストを取得する
5. **テキストオーバーライドの罠**: `get_design_context` はコンポーネントのデフォルトテキストを返すことがあり、Figma上のインスタンスでオーバーライドされたテキストが反映されない場合がある。必ず `get_screenshot` で実際の表示テキストと照合し、差異があればスクリーンショットの内容を正とする

```
× インラインに本文がない → 「取得できなかった」と判断 → スクリーンショットから推測
○ インラインに本文がない → 出力ファイルパスを確認 → Read/Grep で読む → 正確なテキストを使用
```

## Figmaテキスト抽出ルール（必須）

Figma MCPの `get_design_context` で取得したテキストを入稿する際、以下を厳守:

1. **全`<p>`タグを確認**: 1つのノード内に複数の`<p>`がある場合、すべて結合する。最初の`<p>`だけ取って終わりにしない
2. **スクリーンショットで照合**: テキスト入稿後、必ず `get_screenshot` で取得した画像と見比べて漏れがないか確認する
3. **HTMLエスケープ確認**: テキストに `<br>` 等のHTMLを含む場合、出力がエスケープされないか確認する（PHP: `the_field()` などエスケープしない関数を使用 / 静的HTML（gulp-file-include）: 直接記述すれば素通し）

```
× 1つ目の<p>だけ取得 → description: '1行目のテキスト'
○ 全<p>を結合       → description: '1行目のテキスト<br>2行目のテキスト'
```

## Figma データ取得戦略（必須）

### ページ全体のノードを一括取得しない

ページ全体のFigma URLを受け取った場合でも、**一括取得は禁止**。
以下の手順で最小単位ずつ取得すること:

1. まずページ全体の**メタデータのみ**取得（子ノードのID・名前一覧）
2. セクション単位でノードIDを特定
3. **1セクションずつ** `get_design_context` で取得
4. 各セクション内でも、複雑なコンポーネントは個別ノードで取得

### 理由
- 大量データを一括取得するとコンテキスト圧縮で詳細が失われる
- フォントサイズ・letter-spacing・色など、Figma値の厳守ルールが機能しなくなる
- 1セクションずつ取得→コーディング→次のセクション、の繰り返しが最も正確

## 注意事項

- 指示を待たずに最後まで実行すること
- 画像パスは工程 2 で命名済みのファイル名を使用すること（仮のパスは使用しない）
- 工程 2 でリネームした画像ファイル名を参照して、正しいパスでコーディングすること
