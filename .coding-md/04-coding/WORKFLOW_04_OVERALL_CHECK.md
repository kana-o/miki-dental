# 工程 4 補足: 全体整合性チェック

## 概要

コーディング完了後、ページ全体を通した**整合性・動作確認**を行います。
HTML記述ルール（セマンティック・BEM・画像実装等）は `html-check` Skill を参照。
SCSSルールは `scss-check` Skill を参照。

## チェック項目

### 1. HTML / SCSS の整合性

- [ ] HTMLで使用しているクラスがすべてSCSSに定義されているか
- [ ] SCSSに定義されているクラスがHTMLで使用されているか（未使用クラスは削除）
- [ ] クラス名の命名がページ全体で統一されているか

### 2. 画像ファイルの整合性

- [ ] HTMLで参照している画像ファイルがすべて存在するか
- [ ] 画像パスが正しいか（WP: `get_template_directory_uri()` / 静的: `/assets/img/...` の絶対パス）
- [ ] WebP + 元形式（jpg/png）の両方がビルド出力先（WP: `assets/img/` / 静的: `public_html/assets/img/`）に存在するか

### 3. リンクの整合性

- [ ] 内部リンクのパスが正しいか（現時点では `#` でも可）
- [ ] 外部リンクに `target="_blank" rel="noopener noreferrer"` があるか

### 4. レスポンシブ対応

- [ ] すべてのセクションでSP表示が崩れていないか
- [ ] タブレット表示で問題がないか

### 5. ブラウザ確認

- [ ] Chrome / Safari / Edge で表示が正しいか

### 6. パフォーマンス

- [ ] 不要なCSS・JSが含まれていないか
- [ ] 使用していないSCSSクラスが残っていないか

## チェック手順

### クラスの整合性確認

- HTML/PHP 側のクラスは Grep で `class="..."` を抽出
- SCSS 側のクラスは Grep で `^\.[a-z][a-z0-9_-]*` を抽出
- 両者を突き合わせて未定義クラス・未使用クラスを洗い出す

### 画像ファイルの存在確認

- ビルド出力先（WP: `assets/img/` / 静的: `public_html/assets/img/`）を Glob で一覧
- HTML/PHP 内の `assets/img/...` パスを Grep で抽出して照合

### レスポンシブ確認

ブラウザの開発者ツール（DevTools）でモバイル表示に切り替えて確認。

## 最終チェックリスト

- [ ] HTML / SCSS のクラスが一致している
- [ ] 画像がすべて正しく表示されている
- [ ] リンクが正しく機能している
- [ ] SP / PC 両方で表示が崩れていない
- [ ] 主要ブラウザで問題がない
- [ ] 不要なコードが残っていない
